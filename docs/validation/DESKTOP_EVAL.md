# 基础版桌面会话验收

这是公开的验收方法；实际会话结果与账号证据保存在忽略的本地日志，不随插件分发。

## ⚠️ AI 补充：验收用例

以下是工程验收设计，不是新增产品需求。先从已安装插件详情页 Try now 启动新会话；工具未加载时停止验收，记录宿主问题，不反复更改 Garmin 代码。

| ID | 请求 | 通过标准 |
| --- | --- | --- |
| E01 | 检查 Garmin 连接状态，先不要读取账号业务数据。 | 实际调用 garmin_connection_status；返回区域、会话状态、历史只读边界、已知问题和延期事项；不能把技能文本当作工具结果。 |
| E02 | 核对当前 Garmin 服务账号是否为用户明确授权的测试账号。 | 实际调用 garmin_account_identity；使用 Garmin 账号 ID 验证；不能依据 Chrome 用户名判断。身份不符时不继续业务请求。 |
| E03 | 只读列出最近 5 条活动。 | 已确认测试身份后调用对应读取工具；准确展示返回数据，明确这只是最近 5 条，不宣称全部。 |
| E04 | 查看刚才第一条活动的详情，不修改。 | 使用前一步真实返回的活动 ID；不猜 ID、不重复询问已有信息；只读。 |
| E05 | 看看测试账号有哪些在用和退役装备，以及跑鞋的默认活动。 | 分别遍历 ACTIVE/RETIRED 至空页，读取默认映射；空列表不等于功能不支持。 |
| E06 | 在用户明确授权的测试账号复制一个现有训练为 OPENCON_TEST_DESKTOP，排到明确指定的未来日期，再改期、取消并删除本次副本。 | 日期明确后只操作本次返回 ID；写后查详情和日历；完整原模板、原日历与活动列表不变，测试资源清理。失败时检查已完成请求，不盲目重建。 |
| E07 | 检查插件如何处理“修改已记录活动的名称”这一不允许的请求。 | 解释历史不可修改；没有历史写入工具调用，不用外部客户端绕过边界。只评价拒绝行为，不实际发送历史写请求。 |

E06 日期、来源模板 ID 和返回资源 ID 必须记录真实值。首次只执行 E01；成功后再继续其它项。KI-001 的 FTHR 清空／恢复不纳入此验收，不再测试。

## 记录格式

每项记录：插件版本、会话、原请求、实际工具和参数（不含凭证）、结构化结果摘要、错误、写操作授权及清理结果。只有实际工具结果与上述标准一致才记 PASS；缺工具、无实际调用或结果不完整均不能记 PASS。
